2. CORRECTIONS DE BUGS CRITIQUES
═══════════════════════════════════════════════════════════════

BUGS API BITGET V2 CORRIGÉS :

  1. Ordres Market incluent le prix (🐛 CORRIGÉ)
     Avant : Le payload contenait un champ "price" même pour les ordres market
     Erreur : 404 Not Found de Bitget
     Correction : Suppression de la clé "price" du payload market

  2. Incohérence de casse productType (🐛 CORRIGÉ)
     Avant : Usage incohérent (umcbl, USDT-FUTURES, usdt_futures)
     Erreur : Échecs de validation de paramètres
     Correction : Toujours normaliser en "USDT-FUTURES" (forme canonique)

  3. Décalage d'horloge (âge négatif) (🐛 CORRIGÉ)
     Avant : L'âge du ticker pouvait être négatif (timestamp futur)
     Logique : age_ms = received_ms - exchange_ts
     Correction : Plafonner à max(0, age_ms), logger [CLOCK_SKEW]

  4. Mapping TP/SL ignoré (🐛 CORRIGÉ)
     Avant : TP/SL définis comme champs d'ordre, ignorés par l'exchange
     Erreur : Positions sans protection stop-loss
     Correction : Attacher via un appel séparé /api/v2/mix/order/place-tpsl-order

  5. Échecs silencieux (🐛 CORRIGÉ)
     Avant : Les erreurs retournaient None, pas de logs
     Erreur : Les ordres disparaissaient silencieusement
     Correction : Tous les échecs loggés [REJECT], [EXEC] ERROR, [HTTP_FAIL]

BUGS D'EXÉCUTION CORRIGÉS :

  6. Pas de hook d'auto-exécution (🐛 CORRIGÉ)
     Avant : Signal validé mais jamais exécuté (clic UI manuel requis)
     Erreur : Pas de trading automatique malgré la config
     Correction : Appeler execute_signal() immédiatement après validation dans l'orchestrateur

  7. Pas de protections (🐛 CORRIGÉ)
     Avant : Pas de kill-switch, pas de cooldown, pas de max trades/jour
     Erreur : Trading illimité, risque d'explosion
     Correction : Vérifications pré-vol avec 8 protections :
        Kill-switch (arrêt d'urgence)
        Cooldown (temporisation des tirs rapides)
        Max trades par jour (global)
        Max trades par symbole
        Validation RR minimum
        Vérification géométrie TP/SL
        Dédoublonnage de signaux
        Détection mode paper

3. PROTECTIONS API (Vérifications Pré-Vol)
═══════════════════════════════════════════════════════════════

Chaque ordre passe 8 vérifications avant exécution :

  1. Statut Kill-Switch
      Retourne : [REJECT] reason=KILL_SWITCH

  2. Mode de Trading
      Le mode paper bloque l'auto-exécution
      Retourne : [REJECT] reason=PAPER_MODE

  3. Vérification Position Active
      Empêche la double position
      Retourne : [REJECT] reason=POSITION_ALREADY_OPEN

  4. Cooldown Global (300s par défaut)
      Temporise les ordres successifs rapides
      Retourne : [REJECT] reason=COOLDOWN_ACTIVE

  5. Limite Quotidienne de Trades
      Bloque après N trades par jour (reset UTC)
      Retourne : [REJECT] reason=MAX_TRADES_PER_DAY

  6. Limite de Trades par Symbole
      Bloque après N trades par symbole par jour
      Retourne : [REJECT] reason=MAX_TRADES_PER_SYMBOL

  7. Validation Géométrie TP/SL
      LONG : SL < entrée < TP
      SHORT : TP < entrée < SL
      Retourne : [REJECT] reason=INVALID_TP_SL_GEOMETRY

  8. Ratio Risque/Récompense Minimum
      Bloque si RR < MIN_RR (défaut 1.5)
      Retourne : [REJECT] reason=INSUFFICIENT_RR

4. MODES D'EXÉCUTION
═══════════════════════════════════════════════════════════════

TROIS MODES DISPONIBLES :

   MODE SHADOW (AUTO_EXECUTE=shadow)
     - Exécution d'ordres simulée (DRY_RUN)
     - ZÉRO appels réseau (garanti)
     - OrderId simulé : DRY_RUN_<hash>_<timestamp>
     - Logs : [DRY_RUN] WOULD_SEND symbol=... order_id=...
     - Utiliser pour : Tests, validation, simulation 24h

   MODE LIVE (AUTO_EXECUTE=true)
     - Appels API Bitget réels
     - Argent réel en jeu
     - Exécution complète avec TP/SL attachés
     - Logs : [ORDER] ENVOI EN COURS → [EXEC] OK
     - Utiliser pour : Trading en production (commencer avec MAX_TRADES_PER_DAY=1)

   SURVEILLANCE UNIQUEMENT (AUTO_EXECUTE=false)
     - Signaux diffusés uniquement
     - AUCUNE exécution automatique
     - Clic UI manuel requis pour les ordres
     - Utiliser pour : Tests, surveillance, trading manuel

5. RÉFÉRENCE DES LOGS
═══════════════════════════════════════════════════════════════

DÉMARRAGE :
  [BOOT] SMC Engine API initialisée
    TRADING_MODE=live AUTO_EXECUTE_MODE=shadow

OPÉRATION NORMALE :
  [SIGNAL] TROUVÉ | symbol=BTCUSDT direction=long rr=2.0
  [ORDER] PRÉ_VOL_OK symbol=BTCUSDT rr=2.00 direction=long
  
  Mode Shadow :
    [DRY_RUN] ENVOI_SIMULÉ symbol=BTCUSDT entrée=50000 sl=49000 tp=52000
  
  Mode Live :
    [ORDER] ENVOI EN COURS symbol=BTCUSDT entrée=50000 sl=49000 tp=52000
    [HTTP_CALL] méthode=POST opération=MARKET_BTCUSDT_buy
    [HTTP_OK] opération=MARKET_BTCUSDT_buy code=00000
    [EXEC] OK symbol=BTCUSDT order_id=1234567890 fill_price=50010

REJETS :
  [REJECT] symbol=BTCUSDT reason=KILL_SWITCH
  [REJECT] symbol=BTCUSDT reason=COOLDOWN_ACTIVE remaining_sec=250
  [REJECT] symbol=BTCUSDT reason=MAX_TRADES_PER_DAY limit=5 today=5

ERREURS :
  [HTTP_FAIL] status=404 opération=... url=... réponse=Not Found
  [CLOCK_SKEW] symbol=BTCUSDT age_ms=-500
  [STALE_TICKER] symbol=BTCUSDT age_ms=15000

7. PROCÉDURES D'URGENCE
═══════════════════════════════════════════════════════════════

ARRÊT IMMÉDIAT (Kill-Switch) :
  curl -X POST http://localhost:8000/api/bot/kill-switch \
    -H "Content-Type: application/json" \
    -d '{"enabled": true, "reason": "Urgence"}'
  
  Effet : TOUS les ordres suivants BLOQUÉS immédiatement

RETOUR EN SHADOW :
  Modifier .env : AUTO_EXECUTE=shadow
  Redémarrer les services
  Effet : Prochains signaux = DRY_RUN (aucun risque)

DÉSACTIVATION COMPLÈTE :
  Modifier .env : AUTO_EXECUTE=false
  Redémarrer les services
  Effet : Signaux uniquement (clic UI manuel requis)
